## Regla de uso para Codex

Los enlaces de Google Drive son la fuente canónica de originales y rondas visuales. Codex CLI no debe asumir que puede abrirlos si no dispone de autenticación o integración con Drive. Si un enlace no puede abrirse desde CLI, usar la descripción de este archivo y solicitar/sincronizar localmente la referencia antes de tomar decisiones visuales finas.

No reconstruir una referencia visual de memoria cuando el original sea necesario para decidir composición, identidad facial, proporciones o metadata.

# Jerarquía visual actual

Orientación aproximada de uso, no cuota rígida:

- SILENCE ≈ 60%
- SIGNAL ≈ 25%
- TRACE ≈ 15%

`MATTER`, `TRIAD`, `AMBIGUOUS`, `LIVE`, `LAB`, `CONFLICT` y demás territorios editoriales pueden expresarse a través de estos estados; no confundir territorios narrativos con estados visuales.

# Qué debe preservar cualquier implementación

1. La marca debe poder reconocerse sin repetir siempre la misma plantilla.
2. El rojo debe tener función: Axis, Fault, Pulse o Trace; no decoración arbitraria.
3. Waveforms, textura, cinta, marcos técnicos y metadata son recursos opcionales, nunca obligatorios.
4. El blanco debe poder sentirse tenso y deliberado, no vacío por falta de diseño.
5. SIGNAL puede ser muy limpio: negro + fotografía + una anomalía roja puede ser suficiente.
6. TRACE debe ser verificable y documental.
7. Los rostros no se censuran artificialmente; simplemente dejan de ser el centro por defecto.
8. No estirar fotografías ni alterar relaciones de aspecto.
9. Los tres integrantes actuales deben conservar continuidad de identidad.
10. Si dos piezas solo parecen de la misma marca porque comparten la misma plantilla, el sistema falló.
